# Подключение площадок

Подключения создаются в Web UI. Пользователю не требуется вводить JSON вручную: форма показывает только поля выбранной площадки. Перед сохранением можно выполнить безопасную проверку — она не создаёт публикацию.

## Telegram

Поля:

```text
Bot token
Канал / chat_id
```

Проверка выполняет `getMe → getChat → getChatMember`, убеждается, что бот видит канал и имеет статус администратора/создателя с правом публикации. Поддерживается одно изображение и альбом до 10 изображений. Если текст длиннее Telegram caption, изображение/альбом публикуется первым, затем текст отдельным сообщением.

## MAX

Поля:

```text
Access token
Channel / chat ID
```

Используется Bot API `platform-api2.max.ru`. Проверка выполняет `GET /me` и `GET /chats/{chatId}/members/me`, затем требует владельца канала либо администратора с permission `write`. Изображения при публикации передаются как публичные HTTPS URL, поэтому `PUBLIC_BASE_URL` должен быть доступен серверам MAX.

## VK

Поля:

```text
Access token
Group ID
API version
```

Проверка вызывает `photos.getWallUploadServer` для указанной группы, то есть заранее проверяет именно способность токена начать реальную загрузку изображения на стену. Публикация выполняется через `photos.getWallUploadServer → upload → photos.saveWallPhoto → wall.post`. Для защиты от дублей в `wall.post` передаётся `guid = post.id`. На текущем API для загрузки фото может потребоваться пользовательский токен; неподходящий community token способен вернуть ошибку 27.

## Instagram

Поля:

```text
Access token
Instagram User ID
Graph API version
```

Версия Graph API задаётся явно и не зашита в приложение, поскольку Meta выводит версии из эксплуатации по расписанию. Проверка запрашивает `id,username` выбранного профессионального Instagram-аккаунта. Текущая версия Publikator поддерживает один JPEG на пост: `/{ig-user-id}/media → /media_publish`. `PUBLIC_BASE_URL` должен быть публичным HTTPS URL, доступным серверам Meta.

## Повторы и неопределённый результат

Автоматический retry выполняется только для ошибок, которые можно классифицировать как временные, например rate limit или 5xx. Если после начала внешнего POST возникает неклассифицированная сетевая/транспортная ошибка, Publikator ставит цель в `RECOVERY_NEEDED`: публикация могла фактически пройти, поэтому автоматический повтор создавал бы риск дубля.
