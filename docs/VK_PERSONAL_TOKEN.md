# Личный ключ VK для фото и видео

Нужен пользовательский ключ VK API с правами `photos` и `video`. Для публикации на стене также используется `wall`; пользователь должен иметь доступ к выбранному сообществу. Сам по себе успешный вход через VK ID не подтверждает эти возможности.

## Если у вас уже есть приложение с доступом к VK API

1. Используйте **своё** приложение, которому VK разрешает нужные методы. Возьмите его Client ID и настройте разрешённый Redirect URI. Client secret остаётся только на сервере.
2. Для встроенного подключения администратор Publikator задаёт `VK_OAUTH_CLIENT_ID`, `VK_OAUTH_CLIENT_SECRET` и `VK_OAUTH_REDIRECT_URI`. Redirect URI должен точно совпадать с настройками приложения и вести на `/api/vk/oauth/callback` вашей установки. Один лишь адрес локального Publikator не заменяет настройку приложения.
3. В «Соцсетях» запустите авторизацию VK и подтвердите доступ на странице VK. Publikator запрашивает `wall,groups,photos,video,offline`, обменивает одноразовый код на сервере и проверяет полученный ключ. Выданные права и срок действия определяет VK, а не список scope в ссылке.

**Для уже подключённого сообщества:** не переподключайте его общей кнопкой OAuth ради дополнительного ключа. Текущий общий callback обновляет основное подключение для той же стены. Чтобы сохранить ключ сообщества, используйте отдельное действие **«Личный ключ для фото и видео»**, описанное ниже.

## Если пользовательский ключ уже получен официально

1. Откройте Publikator → «Соцсети» → нужное подключение VK → **«Личный ключ для фото и видео»**.
2. Вставьте только пользовательский access token в **«Пользовательский ключ VK»** и нажмите **«Сохранить и проверить»**. Не вставляйте Client ID, Client secret или пароль.
3. Проверьте результаты отдельно для фото и видео. Затем создайте технический пост с фото и MP4, выберите только нужное сообщество и выполните публикацию. Успешный вход или сохранение ключа не заменяют реальную отправку.

Этот отдельный путь добавляет ключ загрузки к существующему подключению; основной ключ сообщества не нужно вводить заново. Сохранённые секреты не возвращаются в интерфейс.

## Если подходящего приложения нет

Не начинайте со старых инструкций «создайте Standalone»: доступность такого создания и прав для нового приложения здесь не подтверждена. Создание приложения VK ID само по себе также не гарантирует доступ к `photos.getWallUploadServer` и `video.save`.

Нужен ответ поддержки/кабинета разработчика VK о доступе вашего приложения к этим методам. Готовый текст обращения:

> Нужен официальный пользовательский access token для собственного сервиса Publikator: загрузка фотографий через photos.getWallUploadServer/photos.saveWallPhoto и видео через video.save, затем wall.post в своё сообщество. Подскажите доступный сейчас тип приложения, процедуру получения этих прав и поддерживаемый OAuth flow. Client ID: [ID приложения, если есть]. Создание нового legacy Standalone-приложения мне недоступно. Секреты и токены к обращению не прикладываю.

Ошибка `application is blocked` относится к приложению, через которое идёт авторизация; добавление `video` её не исправляет. Повторная выдача ключа нужна после изменения разрешений; ранее выданный ключ автоматически новые права не получает.

## Официальные основания и границы проверки

- [Официальный VK PHP SDK: Authorization Code и Implicit Flow](https://github.com/VKCOM/vk-php-sdk/blob/master/README.md). Это описание протокола, а не подтверждение доступа нового приложения к методам.
- [Официальная схема photos](https://github.com/VKCOM/vk-api-schema/blob/master/photos/methods.json).
- [Официальная схема video](https://github.com/VKCOM/vk-api-schema/blob/master/video/methods.json).
- [Официальный VK ID SDK](https://github.com/VKCOM/vkid-web-sdk): получение токена входа не является проверкой публикационных методов.

VK-OAUTH-VIDEO-001: исправлен запрос `video`; сохранённые ключи, схема БД и настройки ботов не мигрируются. Проверки OAuth используют тестовый провайдер. Реальная публикация VK считается подтверждённой только после отправки с подходящим пользовательским ключом и проверки результата на площадке.
